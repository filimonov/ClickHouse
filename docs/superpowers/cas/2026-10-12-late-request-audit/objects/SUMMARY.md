# Аудит опоздавших запросов CAS: сводка {#noclock-audit-summary}

База `d76b59f9295` (`altinity/antalya-26.6-20261008`). 15 read-only отчётов в `docs/superpowers/cas/2026-10-12-late-request-audit/objects/<id>.md`, ~330 сценариев.
Все вреды **выведены** из кода; ни один сценарий не воспроизведён, TLC не запускался.

## Главное {#main}

- **Самые опасные дыры не про время.** Потеря данных достижима у живого писателя с валидным lease (гонка `HEAD`/`GET` в `.meta`, orphan sweep до создания namespace), у двойника с тем же `uuid` (неоднозначная выдача epoch) и у GC, у которого lease нет вообще (повтор SDK + точный delete). Ни lease, ни дедлайн в транспорте их не закрывают.
- **Где безопасность держится на времени**, вред ограничен: устаревшие файлы MergeTree в `_files/` (фантомная мутация после рестарта), заклинивший `DROP`, потерянная подтверждённая запись ref-log (R4), сертификат смерти держателя (запас 22–27 с). Запас по времени реальный, но только «на бумаге»: транспорт ограничивает операцию сокета, а не попытку.
- **Хранилищем уже защищены:** снимки и `_ckpt`, ref-ключ, манифесты против обычных опозданий, управление GC, `_pool_meta`/`_probe`, слот mount как объект.
- **Почти всё закрывается без смены формата**, малыми правками (5–100 строк каждая). Формат нужен только для ревизии каталога и, опционально, для `_files` как ref.

## Таймауты и Poco {#timeouts}

- **Сегодня:** резерв `2E+M` считает, что попытка длится не больше `E` = 7 с. Транспорт ограничивает каждую операцию сокета отдельно (`SocketImpl::sendBytes/receiveBytes`), поэтому попытка не ограничена. Publish блоба идёт с профилем по умолчанию: 500 повторов, допуск один раз до вызова.
- **Дедлайн в транспорте (17b):** атомарное значение уже есть (`mount_fence.deadline_boot_ms`). Хук — через `IHTTPSessionDataHooks::atStart` в `src/IO`, около 170 строк, `base/poco` не нужен. Безопасность зависит только от момента ухода последнего байта.
- **Что это даёт:** закрывает транспортные сценарии TR2–TR10. Позволяет убрать `E` как единицу резерва, оба неравенства `validateCasRequestBudget` (остаётся `P + M < L`) и per-call бюджеты. Запись идёт до ~27-й секунды вместо 14-й.
- **Что не даёт:** не трогает GC (lease у него нет), пункты 1–5 таблицы выше, паузу между проверкой и `send`, позднее применение хранилищем.
- **Открытые вопросы:** thread-local scope не покрывает параллельные `publish`/`stream`; доходит ли таймаут до `SSL_write`; `TCP_USER_TIMEOUT` есть только в Linux.

## Дополнение: осиротевший маркер после удаления тела {#orphan-meta}

- Падение сервера между удалением тела и маркера **до** коммита раунда безопасно: задания маркеров дренируются до CAS `gc/state` (`meta_pool_wait`), новый лидер повторяет раунд, `performRedeleteIo` → `Gone` → снова `scheduleConfirmedMetaDelete` (V).
- Упавшее задание удаления маркера проглатывается (`GcMetaWriter::submit`, `CASGCMetaWriteAnomaly`), раунд коммитится, запись выбрасывается → маркер навсегда (V). Зачистки `.meta` без тела нет (V, grep).
- Вред: утечка + **ложная ERROR** fsck `meta_without_body` (INV-META-BODY; комментарий в `CasFsck.cpp` утверждает, что так не бывает). Данным не вредит: следующий писатель хеша переводит `Condemned` → `Clean`.
- Фикс (в P3): держать запись до подтверждённого удаления маркера (~30 строк) или зачистка осиротевших маркеров при LIST (~40); fsck → WARNING (~5).
