# Темы исследования: итоговый список {#noclock-topics}

Источник: `inventory.md` (opus, 101 строка, U1–U15) + `inventory-codex.md` (проверка полноты). База `d76b59f9295`.
Все сценарии — **выведены** из кода, не исполнены.

| # | Тема | Строки / откуда | Суть | Класс работы |
|---|---|---|---|---|
| T1 | Повтор тела блоба | U1 (B9), сужено codex | SDK повторяет тот же `PUT`/`copy` → старый content-ETag → поздний точный `delete` GC удаляет живой блоб. Повтор `CompleteMultipartUpload` объект не пересоздаёт (`NoSuchUpload`) | исследование |
| T2 | Несвязанное примирение тела и `.meta` | U2 (M3) + codex: синтетический успех multipart | `reconcileMetaClean` пишет `Clean` поверх `Condemned`, не доказав, что тело — наша публикация; `NoSuchUpload` + любой объект по ключу = «успех» | исследование |
| T3 | Общие изменяемые пути | U3+U4 (P1, P2, R1, R2) | `_files/`, `roots/<srid>/`: ключ общий у зомби и преемника, запись и удаление по намерению, не по версии | исследование (главная, формат/миграция) |
| T4 | Устаревшее право удаления | U5 (C6) | `beginRemoving` сравнивает строку каталога по значению → поздний `DROP` зомби | исследование |
| T5 | ABA каталога и повтор отставленной жизни | NEW codex (C2, C8, L6, K3, P4) | у каталога нет ревизии: добавление+удаление восстанавливает те же байты и ETag; отменённая жизнь воскресает; janitor удаляет объекты воскресшей жизни | исследование |
| T6 | Неоднозначная выдача epoch | NEW codex (E1) | A ждёт ответа на запись `N+1` по таймауту, B пишет те же байты, A при разрешении видит «свои» → оба получают epoch `N+1` | исследование (короткое) |
| T7 | Принятие той же пары в слоте | U8 (MT2) | `claimMount` переписывает слот при том же `(uuid, epoch)`; на `3b4037ae265` отказ. С T6 — достижимо в проде | прямой фикс |
| T8 | Немонотонный reclaim и supersession | NEW codex (MT3, C4, C5, MT9) | reclaim требует «другой», а не «больший» epoch; `SupersededEpoch` = любое неравенство | прямой фикс |
| T9 | Очистка staging | U9 (ST4) | LIST + слепое удаление по общему префиксу после claim, мимо `CasRequests` | прямой фикс |
| T10 | Устаревшее relink-подтверждение | U10 (X1) | `Yes` из памяти; `404` следующего слота не доказательство | исследование |
| T11 | Устаревшие чтения | U11 (X2, B7) + codex: read pipeline | устаревшие `SELECT`, чтение удалённых блобов; чтения идут ещё и через кеш/prefetch | исследование (вред — доступность, не потеря?) |
| T12 | Стирание epoch и переиспользование идентичности | U13a (MT10, E3, O3) | decommission удаляет `mount`/`epoch` → тот же uuid снова получает epoch 1 | исследование |
| T13 | Отставка владельца против живого преемника | U13b | tombstone `owner` в окне, где преемник уже жив | вместе с T12 |
| T14 | Временные допущения (сквозная) | U6+U7+U14 + MT7 | сертификат смерти по часам, разрыв «допуск → отправка», drain при farewell не гасит висящие запросы | не отдельный фикс: что останется от времени после T1–T13 |

Снято: U12 (recovery читает историю преемника, вредной мутации нет — codex). Вне CAS: U15 (Keeper/RMT).

Модели TLA+ по codex неверно процитированы для: MF1, L1, K1, C4/C5, X1, X3/MT3/MT4/MT8. Ни одна модель не покрывает T3, T5, T6, T8, T9 и позднюю запись после допуска.
