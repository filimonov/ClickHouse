## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
During a store outage StorageReplicatedMergeTree::fetchPart / fetchExistsPart find an Outdated part with the same name, wake the cleanup thread and return false without postponing the queue entry. Cleanup fails with NETWORK_ERROR (210) because part removal is refused while writes are paused, and the fetch reruns at once. Measured on the fault-proxy stand (tmp/cas405/REPORT.md): ~1000 iterations/s, 40k-140k error lines and ~1 GB of log per node per 120 s outage, on base 8fefc27bd62 and #2517 d410298e2c4. The loop is in upstream code; CAS triggers it by refusing removal for the whole pause.
