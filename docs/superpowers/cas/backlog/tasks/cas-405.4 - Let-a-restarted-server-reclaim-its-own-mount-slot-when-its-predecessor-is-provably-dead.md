## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
After kill -9 a server waits 1.05 x lease + renew period before it can mount (163 s with a 120 s lease) and is unreachable meanwhile. Idea: store boot id and process start time in the lease body (optional plain keys; format frozen since 26.6.4) so a restart on the same host can prove the old process is gone. Until then document cas_unsafe_remount_no_delay for one-process-per-uuid deployments. Data: tmp/cas405/REPORT.md.
