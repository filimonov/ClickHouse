## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
A process killed mid multipart upload in S3 staging (`staging_backend=s3`) leaves an incomplete MPU under `staging/<srid>/`. Object LIST does not show it, so `sweepOwnMountStaging` never removes it; the parts stay billed forever (audit docs/superpowers/cas/2026-10-12-late-request-audit/objects/staging*.md, S7).

The member-lifecycle spec (docs/superpowers/specs/2026-10-13-cas-member-lifecycle-design.md, #staging) only documents the bucket lifecycle rule `AbortIncompleteMultipartUpload` (owner decision 2026-10-13). This task is the code alternative: at mount start, `ListMultipartUploads` under `staging/<srid>/` and abort uploads whose key epoch is below the live epoch (keys carry the writer epoch after that spec). Check request support on S3, GCS and RustFS first.
