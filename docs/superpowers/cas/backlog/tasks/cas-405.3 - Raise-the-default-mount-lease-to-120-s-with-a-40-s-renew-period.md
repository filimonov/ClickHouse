## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
With 30 s, GC fenced a live node that alone lost the store after 49 s (1.05 x lease + renew period); with 90 s and 120 s a 120 s single-node outage was not fenced. Inserts are admitted 64-104 s into an outage instead of 4-14 s. Cost: crash restart waits 163 s instead of 43 s; GC fences a dead member after ~286 s instead of ~190 s. 180 s rejected: crash restart 243 s. Lands after #2517. Data: tmp/cas405/REPORT.md.

## Implementation Notes

2026-11-11 defaults review: amend the proposal to 120 s / 10 s, not 120 s / 40 s. Same 90 s outage: 120/40 gave 39 INSERT errors from 84 s (`l120_hang90`), 120/20 gave 2, 120/10 gave 4 (`l120r10_hang90`, `rec_hang90`); a 90 s process stall: 4 errors at 120/40, 0-1 at 120/10. The renew period subtracts one for one from the guaranteed tolerance and costs one small PUT per period (otel.demo p99 105 ms). Cost of 120/10 measured: GC fences a killed member after 224 s, an immediate restart is ready after 138 s (30/10: 103 s and 43 s). Report: docs/superpowers/reports/2026-11-11-cas-defaults-review.md on branch cas-297-defaults-review (worktree ~/workspace/ClickHouse/cas-297-defaults); run data master/tmp/cas297/runs; binary PR 2805 @41d4a78eeb9.

2026-11-12 defaults review: one more case for the lease default: creating 1000 tables through a slow store with no fault injected fails at 30/10 (603 of 1000 CREATE TABLE on the second node refused: `read of 'cas/ref_catalog': no lease budget for the reissue`, run `mt1000_def_hang30`) and succeeds at 120/10 (1000 of 1000, `mt1000_hang90`). Report v2: docs/superpowers/reports/2026-11-11-cas-defaults-review.md on branch cas-297-defaults-review (f9ec0861aff); run data master/tmp/cas297/runs; binary PR 2805 @41d4a78eeb9.

2026-11-12 correction after an independent check of the report against run data (docs/superpowers/reports/2026-11-11-cas-defaults-review.check.md.txt, a49f8a8e45f): two refinements. (1) The first error of a 90 s outage at 120/10 (80-86 s) is a request-window error, not a lease refusal; lease refusals start at about 104 s (`rec_hang120`). (2) A longer lease does help beyond 90 s: on a 120 s outage 180/60 had 2 errors, 120/10 had 99, 120/40 had 240. 120/10 is the choice for a 90 s target; a 120 s target needs about 150/10 (not tested) or 180.

2026-11-13: PR https://github.com/Altinity/ClickHouse/pull/2831 (branch head a3967637843, draft, not merged). Commits b528b234dca "Default the CAS mount lease to 120 s" and 9dbc97f3e19 "Print the write reserve and the renewal slack at mount" cover: #1 default lease 120 s with renew period kept at 10 s (not the 40 s of the title), docs state the restart wait (about 138 s) and the GC fence wait (up to two GC intervals after the lease threshold), upgrade note requires pinning `cas_mount_lease_ttl_ms` to `30000` while a pool has a build without the declared-lease rule (CAS-475). Still open: #2 stand rerun (not run). The default is under an open decision (CAS-480): CI of the head shows a restart after a hard kill waits about 131 s before the server listens (36.5 s at 30 s). That fails the regression hard-restart scenarios, `test_backup_restore_on_cluster::test_shutdown_waits_for_backup` and the stress arm_release lane. The criterion is implemented, but the default may be reverted or pinned to 30 s in tests (integration configs that kill a server already pin 30 s). CI run https://github.com/Altinity/ClickHouse/actions/runs/43379266824. Evidence on the head tree: `CAS*` gtests 3052 passed (release) and 3056 (ASan), 59 of 59 `*_cas_*` stateless tests.
