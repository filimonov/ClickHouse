## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`Retry::standard`, `once` and `untilLeaseSafe` use a fixed 90 s window (`Backend/CasRetry.h:39-55`). Once the mount lease is 120 s this window causes every remaining client error of a store outage: requests in flight when the outage begins (`stageManifest`, the `_ckpt` publication, reads) give up at 82-90 s. Stand runs on PR 2805 @41d4a78eeb9 (tmp/cas297/runs): `l120r10_hang90` 4 INSERT errors at 81 s, `l180_hang90` 2 at 83 s, `rec_hang90` 4 at 80 s, `rec_50390` 3, `rec_readstall90` 2 at 86 s; read stalls at the default lease the same (`def_readstall90`). No lease length removes them. Proposal: one disk setting (for example `cas_request_window_ms`), default 120000 or more = target stall 90 s + one attempt envelope 7 s + one backoff 5 s with margin; `recovery_retry_budget_ms` (120 s, `Backend/CasRequestBudget.h`) must stay at least twice the window. Report: docs/superpowers/reports/2026-11-11-cas-defaults-review.md (branch cas-297-defaults-review).
<!-- SECTION:DESCRIPTION:END -->
