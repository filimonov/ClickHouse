The renewal thread allocated under the global memory tracker, so a server near `max_server_memory_usage` could throw `MEMORY_LIMIT_EXCEEDED` inside a lease renewal. The loop's catch-all then fenced the mount and ended the renewal thread for good, and the mount went through a remount under a fresh epoch because of memory pressure that had nothing to do with the object store. The renewal now survives the server memory limit.

**Why it matters for the lease**

The lease thread is the one thread that must not die first: without a renewal the holder loses its slot after the observation window, its unfinished work loses GC protection and every writer waits for the remount. The next change of the series (https://github.com/Altinity/ClickHouse/issues/2431) makes the renewal retry through an object-store outage instead of giving up; that promise needs a renewal thread that cannot be killed by the state of the server itself.

**Changes**
- `LockMemoryExceptionInThread(VariableContext::Global)` for the whole renewal iteration, result handling included: the tracker still counts this thread's allocations but never throws on them. `Global`, because a `User`-level lock leaves the server limit enforced. Precedents: `KeeperServer`, `TransactionLog`. `std::bad_alloc` stays terminal.
- Conditional writes set `s3_allow_parallel_part_upload = false`, so the `PUT` runs on the calling thread and the guard covers it. This applies to every Native conditional write (lease, manifests, `gc/state`, ref ledger); a body above `max_single_part_upload_size` on an ETag store now uploads its parts one after another, on a call that already waits for the whole write.
- The conditional `PUT` buffer opens at `min(body size, 1 MiB)` instead of 1 MiB: a 200-byte control-plane write no longer costs a megabyte per attempt.

**Risks / notes**
- Until the renewal rework lands, a memory-limit exception inside the remount worker still costs one remount attempt, not the thread.
- Rejected: `MemoryTrackerBlockerInThread` (hides accounting), a deterministic classification of the error, a longer budget.

**Testing**
- Regression test: the global limit is exceeded on the lease thread before the request, inside it and while the result is handled; the thread stays alive, the mount stays `Live`, `CASMountLeaseLost` does not move. Red on the base; red again with the guard at `User` level or below the admission block.
- Behaviour-preservation tests: `std::bad_alloc` inside a renewal stays terminal; a 3 MiB conditional object is one `PUT` with every byte.
- Tests for the calling thread and the buffer size (red on the base).
- `CAS*` gate: 2613 (release), 2617 (ASan, no error); `S3SingleAttemptClient.*` under ASan; `test_cas_mount_renewal_retry`: 4 passed.

Closes: https://github.com/Altinity/ClickHouse/issues/2403
Closes backlog task CAS-292.
